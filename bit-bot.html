Aperçu

Bit-Bot est une application web sans installation, un seul fichier HTML : un visage de robot animé à qui l'on parle par la voix ou le texte, qui répond via un fournisseur IA au choix (ou un mode démo entièrement hors ligne). Il se jumelle en option à un BBC micro:bit via Web Bluetooth, reflétant les émotions et commandes sur l'écran LED 5×5 du micro:bit et relisant ses capteurs pendant les jeux.

Toute l'application — interface, système de traduction, appels IA, gestion Bluetooth — vit dans un seul index.html, plus une page flash.html séparée pour obtenir le firmware du micro:bit compagnon et quelques fichiers microbit_makecode_*.js avec le code source de ce firmware.

Démarrage rapide

  1. Ouvre l'application en ligne dans Chrome ou Edge (les API Web Bluetooth et Speech sont requises, donc Safari/Firefox ne fonctionneront pas pleinement).
  2. Parcours l'intégration en 4 étapes : nomme ton robot, choisis une personnalité, connecte éventuellement un micro:bit.
  3. Appuie sur le micro 🎤 ou tape un message, puis envoie. Le robot répond dans la bulle de discussion et le dit à voix haute.

Étape par étape : cloner, flasher & tester

Ce parcours amène une copie vierge du dépôt jusqu'à un robot pleinement fonctionnel — discussion texte, voix, et (en option) un micro:bit jumelé — sans rien supposer d'autre que d'avoir Chrome ou Edge installé.

1. Cloner le dépôt

git clone https://github.com/abourdim/bit-bot.git
cd bit-bot

2. Servir le site en local

Aucune étape de build — c'est du HTML/CSS/JS pur — mais les API Web Speech et Web Bluetooth refusent toutes deux de fonctionner depuis un simple chemin file:///, donc sers le dossier via HTTP :

python3 -m http.server 8000

Puis ouvre http://localhost:8000 dans Chrome ou Edge.

3. Obtenir le firmware du micro:bit (optionnel)

Passe cette étape entièrement si tu veux seulement tester la discussion texte/voix. Sinon, ouvre flash.html, appuie sur Copier le code micro:bit, colle-le dans l'onglet JavaScript d'un nouveau projet makecode.microbit.org, ajoute l'extension bluetooth, règle Paramètres du projet → « Aucun appairage requis », et flashe-le sur la carte.

4. Tester la discussion texte

Sans clé API configurée, l'application démarre automatiquement en mode 🎮 Démo — tape un message et envoie ; tu devrais recevoir une réponse préenregistrée mais fidèle à la personnalité, sans aucun appel réseau. Cela confirme que l'interface et la machine à états fonctionnent avant d'impliquer un vrai fournisseur IA.

5. Tester la voix

Appuie sur le bouton 🎤, autorise le microphone, et parle. Un test réussi affiche le texte transcrit, puis une réponse parlée avec la bouche/les yeux du robot animés pendant qu'il parle.

6. Tester la connexion au micro:bit

Appuie sur le badge de connexion dans l'en-tête, choisis ta carte dans le sélecteur d'appareils Bluetooth, et attends un visage content — à l'écran et sur la grille LED du micro:bit lui-même. S'il n'apparaît jamais, voir Dépannage.

7. Tester un jeu

Ouvre le panneau 🎮 et lance Smart Tilt Quiz. Même sans clé IA et sans micro:bit connecté, il devrait quand même poser une question depuis la banque de secours intégrée (touche les libellés A/B à l'écran, ou incline le micro:bit s'il est jumelé) — confirmant que la logique du jeu et le contenu de secours fonctionnent indépendamment de tout appel réseau.

Une base fonctionnelle ressemble à ceci : des réponses en mode Démo sans clé, la voix en entrée et en sortie, un visage content sur le micro:bit après jumelage, et une question de quiz à laquelle tu peux répondre d'une manière ou d'une autre. Ce n'est qu'après que tout ça fonctionne qu'il vaut la peine de dépanner la clé d'un fournisseur IA spécifique.

Comprendre le code (pour débutants)

Cette section est pour quiconque a l'application en marche et veut ouvrir index.html pour commencer à modifier quelque chose. Elle suppose des bases en JavaScript mais aucune connaissance préalable de ce code. À sauter entièrement si tu veux seulement utiliser l'application.

La forme du fichier

Tout — balisage, CSS et JavaScript — vit dans un seul index.html, long de plusieurs milliers de lignes, en trois blocs : un bloc <style>, le corps HTML (en-tête, carte d'intégration, interface de discussion, panneau de réglages, fenêtre d'aide, panneaux de jeux/commandes), et un grand <script> à la fin sans système de modules — chaque fonction est une simple déclaration function de premier niveau, appelable directement depuis des attributs onclick="..." intégrés dans le HTML.

L'objet state

Un objet unique contient tout ce qui doit persister ou piloter l'interface : statut de connexion, fournisseur IA actuel et ses clés, nom et personnalité du robot, historique de discussion par personnalité, et préférences d'interface comme la langue et le thème. Il est enregistré dans localStorage en JSON à chaque changement pertinent (saveSettings()) et restauré au chargement (loadSettings()) — il n'y a pas d'autre couche de persistance.

Le système de traduction : I18N → tr() → data-i18n

Chaque chaîne visible par l'utilisateur vit dans un objet I18N indexé par langue (en/fr/ar), puis par une clé courte :

const I18N = {
  en: { onb_welcome_title: "Welcome!", ... },
  fr: { onb_welcome_title: "Bienvenue !", ... },
  ar: { onb_welcome_title: "مرحباً!", ... }
};
function tr(key) { return I18N[state.lang][key] ?? I18N.en[key] ?? key; }
function trg(key, vars) { /* tr() plus {placeholder} substitution */ }

Les éléments HTML statiques sont marqués data-i18n="onb_welcome_title" ; applyLang(lang) parcourt chaque élément marqué et fixe son texte depuis tr(). Les chaînes dynamiques (notifications, lignes de journal, narration des jeux IA) appellent directement tr()/trg() depuis le JavaScript. Changer de langue est un seul appel de fonction, setLanguage(lang), qui relance applyLang() et mémorise le choix.

Comment circule un message de discussion : saisie utilisateur → IA → robot

  l'utilisateur tape/parle
       │
       ▼
  sendMessage()  ──▶  addBubble('user', text)
       │
       ▼
  callAI(text)  ──▶  selon state.provider :
       │                     Demo → getDemoResponse() (préenregistré, hors ligne)
       │                     Groq / Gemini / Cohere / Mistral / OpenRouter
       │                       → fetch() vers l'API REST de ce fournisseur
       ▼
  analyse la réponse, retire les balises [command]
       │
       ▼
  addBubble('robot', text)  +  speak(text)  +  sendCommand(emotion)

Le prompt système de l'IA se termine toujours par une directive de langue construite à partir de tr('ai_lang_directive'), afin que le modèle lui-même réponde dans la langue d'interface actuellement sélectionnée plutôt que seul le texte d'interface fixe soit traduit. sendCommand() met à jour à la fois le visage à l'écran et, si un micro:bit est connecté, écrit la même commande via Bluetooth.

Parler au micro:bit : connect(), sendCommand(), handleRx()

connect() appelle navigator.bluetooth.requestDevice() filtré sur le service Nordic UART, puis découvre les caractéristiques TX (notification, micro:bit→navigateur) et RX (écriture, navigateur→micro:bit). Chaque commande sortante — une émotion, une entrée de jeu, un mouvement de servo — passe par une seule fonction, sendCommand(cmd), qui l'écrit comme ligne UTF-8 sur la caractéristique RX. Tout ce que le micro:bit renvoie (appuis sur boutons, lectures de capteurs) arrive comme événement characteristicvaluechanged traité par handleRx(), qui analyse la ligne et la répartit — par exemple vers processScienceReading() pendant le jeu Détective Scientifique.

La machine à états de l'intégration

L'intégration est constituée de quatre cartes HTML, une seule visible à la fois, pilotées par un simple entier currentOnboardingStep. nextOnboardingStep()/prevOnboardingStep() l'incrémentent/décrémentent simplement et basculent quelle carte a la classe .active ; completeOnboarding() fixe state.onboardingComplete = true, l'enregistre, et masque toute la superposition pour qu'elle ne réapparaisse jamais sur ce navigateur.

Architecture du système, illustrée

Deux allers-retours indépendants et optionnels se rejoignent au milieu d'un seul onglet de navigateur — l'appel IA et la liaison micro:bit ne se parlent jamais directement, seulement via l'état propre de l'application :

                        ┌─────────────────────────┐
                        │   index.html (browser)  │
                        │  ─────────────────────  │
   🎤 mic / ⌨ keyboard ─▶│  sendMessage()          │
                        │       │                 │
                        │       ▼                 │
   AI provider API   ◀──▶  callAI(text)           │
   (Groq/Gemini/...)     │       │                 │
                        │       ▼                 │
                        │  addBubble()+speak()    │
                        │       │                 │
                        │       ▼                 │
   BBC micro:bit     ◀──▶  sendCommand(emotion)   │
   (Bluetooth LE)        │  handleRx() ◀── sensors│
                        └─────────────────────────┘

Le volet IA se fait en HTTP via WiFi/données (entièrement sauté en mode Démo) ; le volet micro:bit est en Bluetooth LE, jumelé une fois par session de navigateur. L'un ou l'autre peut être absent — l'application est pleinement utilisable sans aucun, avec un seul, ou avec les deux connectés.

La disposition HTML, illustrée

À l'intérieur de <body>, le balisage est une pile plate de superpositions affichées/masquées indépendamment, plus l'écran de discussion toujours visible en dessous :

  <body>
   ├─ #onboarding        assistant de premier lancement, 4 cartes, une .active à la fois
   ├─ #helpOverlay        fenêtre de référence rapide ❓
   ├─ header              drapeaux de langue · badges robot/IA · connexion · firmware · aide · ☰
   ├─ main                visage du robot + bulles de discussion + saisie texte/micro
   ├─ #settingsPanel      panneau glissant : onglets Fun / Setup / Advanced
   ├─ #commandsPanel      aide-mémoire des commandes rapides 📋, par catégorie
   └─ #gamesPanel         🎮 Smart Tilt Quiz / Adventure / Science Detective

Chacun de ces panneaux/superpositions n'est qu'un <div> qui bascule une classe CSS .open (ou .active) via une petite fonction toggleX() — il n'y a ni routage, ni DOM virtuel, ni framework. <head> contient un seul grand bloc <style> intégré avec des propriétés CSS personnalisées (--primary, --surface, etc.) que [data-theme="dark"] redéfinit — c'est tout le système de thème.

Le firmware du micro:bit : microbit_makecode_v3.js

C'est le programme que tu flashes sur la carte elle-même — un monde séparé, bien plus petit que l'application web, écrit dans le dialecte JavaScript/TypeScript de MakeCode. Il n'a aucune notion d'« IA » ou de « discussion » ; tout ce qu'il connaît, c'est un vocabulaire plat de commandes textuelles d'un mot reçues via le Bluetooth UART, et comment réagir à chacune sur la grille LED 5×5.

Les images LED ne sont que du texte

Chaque visage/icône est un appel images.createImage() sur une grille 5×5 de . (éteint) et # (allumé) :

const HAPPY = images.createImage(`
    . . . . .
    . # . # .    ← eyes
    . . . . .
    # . . . #
    . # # # .    ← smile
    `)

Il y a 15 de ces bitmaps dans le fichier — des émotions (HAPPY, SAD, ANGRY, SURPRISED, LOVE, SLEEPY, SILLY, WOW, HAHA, COOL), deux animaux (CAT, DOG), et cinq icônes de jeu (flèches, point d'interrogation, coche, croix, thermomètre, ampoule). Tu veux un nouveau visage ? Copie le motif de points et de dièses de n'importe lequel des existants et change la forme — rien d'autre dans le fichier n'a besoin de le savoir tant que tu ne l'ajoutes pas aussi au gestionnaire de commandes ci-dessous.

Garder le miroir LED du navigateur synchronisé

Chaque fois que le micro:bit change ce qu'il affiche, il renvoie aussi toute la grille de 25 pixels via Bluetooth comme une seule ligne de texte, ce qui alimente le widget miroir LED ⚫ de l'application web :

function sendLEDState() {
    let state = "LED:"
    for (let y = 0; y < 5; y++)
        for (let x = 0; x < 5; x++)
            state += led.point(x, y) ? "1" : "0"
    bluetooth.uartWriteString(state + "\n")
}
function showAndSync(img: Image) {
    img.showImage(0)
    basic.pause(50)   // let the image actually latch before reading it back
    sendLEDState()
}

Presque toutes les animations appellent showAndSync() plutôt que le showImage() brut de MakeCode, précisément pour que le miroir du navigateur ne se désynchronise jamais de la carte physique.

La table de dispatch des commandes

Une seule fonction, handleCommand(cmd), reçoit chaque ligne envoyée par le navigateur et la fait passer par une longue chaîne if / else if comparée mot pour mot en minuscules — il n'y a ni JSON, ni protocole structuré, juste des mots simples :

Commande(s)Ce qui se passe sur la carte
happy, sad, angry, surprised/wow, love, sleepy, silly, haha, cool, cat, dogAffiche le visage/icône statique correspondant.
wave, dance, spin, party, magicJoue une courte animation multi-images, puis revient à HAPPY.
quiz / correct,yes / wrong,no / thinkingVisages d'état de jeu : point d'interrogation, coche + fête, croix + triste, icône « perplexe ».
read_temp / read_lightAffiche une icône, lit le vrai capteur avec input.temperature()/input.lightLevel(), le renvoie sous forme de TEMP:<n>/LIGHT:<n>, et affiche le nombre sur les LED.
left/right/forward/backward, count, dice, rainbowVisuels divers de jeu/utilitaires (flèches, compte de 1 à 5, lancer de dé aléatoire, arc-en-ciel clignotant sur toute la grille).
tout ce qui n'est pas reconnuAffiche un point d'interrogation QUESTION — le firmware ne plante jamais sur un mot inconnu.

Percevoir le monde : inclinaison, secousse, boutons

Trois sources d'entrée fonctionnent indépendamment du gestionnaire de commandes et ne font qu'envoyer des données, jamais en recevoir — c'est ainsi que les jeux côté navigateur reçoivent de vraies entrées de capteurs :

basic.forever(function () {   // polled every loop, ~cooldown-gated
    let x = input.acceleration(Dimension.X)
    if (x < -TILT_THRESHOLD) bluetooth.uartWriteString("TILT_LEFT\n")
    else if (x > TILT_THRESHOLD) bluetooth.uartWriteString("TILT_RIGHT\n")
})
input.onGesture(Gesture.Shake, function () {
    bluetooth.uartWriteString("SHAKE\n")
})
input.onButtonPressed(Button.A, function () {
    bluetooth.uartWriteString("BTN_A\n")
    // ...also shows an icon locally
})

Un INPUT_COOLDOWN partagé (500ms) et des horodatages de « dernier déclenchement » par entrée empêchent une seule inclinaison ou secousse physique d'inonder plusieurs événements dupliqués — la même idée d'anti-rebond que le dispositif de sécurité de 500ms du navigateur dans le projet frère VideoCar, juste appliquée aux gestes plutôt qu'aux commandes moteur.

Premier lancement : intégration

Les nouveaux visiteurs voient une carte d'intégration en 4 étapes avant l'application principale :

ÉtapeCe qui se passe
1. BienvenueIntroduction aux trois fonctionnalités phares : Discussion vocale, Micro:bit, Personnalités.
2. PersonnaliserTape un nom de robot et choisis l'une des 12 personnalités.
3. Connecter le Micro:bitJumelage Bluetooth optionnel, ou « Passer pour l'instant ».
4. TerminéUne carte d'astuce, puis « Commencer à discuter » te dépose dans l'application principale avec un message de bienvenue parlé.

La finalisation est enregistrée dans localStorage, donc l'intégration ne s'exécute qu'une fois par navigateur.

Nom du robot & personnalité

Personnalités disponibles : Enjouée (par défaut), Serviable, Pirate, Spatiale, Héros, Dino, Fée, Ninja, Magicien, Cowboy, Extraterrestre, Sirène. Chacune a son propre ton de prompt système et son propre historique de discussion séparé (jusqu'aux derniers messages par personnalité), donc changer de personnalité ne fait pas perdre la conversation en cours avec une autre.

Le nom du robot est modifiable à tout moment dans Réglages (☰) → Fun. Le champ du nom s'enregistre à chaque frappe (pas seulement en perdant le focus) et affiche une notification de confirmation, il ne peut donc jamais échouer silencieusement à persister.

Chaque prompt IA — la discussion principale et les trois mini-jeux — a une directive de langue ajoutée selon la langue d'interface actuellement sélectionnée, afin que les réponses générées par le modèle lui-même reviennent en anglais, français ou arabe plutôt que seul le texte d'interface fixe soit traduit.

Connecter un micro:bit

Appuie sur le badge de connexion dans l'en-tête (ou pendant l'étape 3 de l'intégration) pour jumeler via Web Bluetooth. Une fois connecté, les émotions et commandes parlées du robot sont reflétées en direct sur la grille LED 5×5 du micro:bit, et l'accéléromètre/les boutons/capteurs du micro:bit peuvent piloter les jeux (voir ci-dessous).

Web Bluetooth nécessite un contexte sécurisé : https:// ou localhost. Ça ne fonctionnera pas ouvert comme simple fichier HTML file:///.

Obtenir le code du firmware

Le côté micro:bit a besoin d'un petit programme MakeCode flashé une fois. Plutôt que d'envoyer les gens sur GitHub copier le code source brut à la main, flash.html est une page dédiée qui :

  • Récupère le microbit_makecode_v3.js actuel au chargement et l'affiche dans un bloc de code défilant.
  • Possède un unique gros bouton Copier le code micro:bit (API presse-papiers avec repli sur execCommand).
  • Liste les six étapes pour le coller dans makecode.microbit.org, ajouter l'extension bluetooth, activer « Aucun appairage requis », et flasher.

Elle est reliée depuis l'onglet Réglages → Setup de l'application principale et depuis un badge dédié Firmware dans l'en-tête.

Commandes & jeux propulsés par l'IA

Le bouton 📋 au-dessus de la zone de message ouvre un aide-mémoire de commandes par catégorie (Émotions, Animaux, Actions, Sons, Fête, Pouvoirs) — touche n'importe quel mot pour le déclencher instantanément.

Le bouton 🎮 ouvre trois mini-jeux propulsés par l'IA, tous jouables avec l'inclinaison/secousse/boutons d'un micro:bit connecté comme entrée :

JeuCe qu'il fait
🎯 Smart Tilt QuizQuestions de quiz à choix multiples générées par l'IA (avec une banque de secours codée en dur si l'appel IA échoue) ; incline à gauche/droite pour répondre ; la difficulté s'adapte à ta série.
🗺️ Adventure ExplorerUne histoire ramifiée narrée par l'IA dans un thème choisi au hasard (forêt, espace, océan, château, jungle) ; secoue pour regarder autour, incline pour choisir.
🔬 Science DetectiveVraies lectures de capteurs (température ou lumière) du micro:bit, expliquées par l'IA dans un langage adapté aux enfants, avec une explication de secours si l'appel IA échoue.

Langues & système de traduction

L'interface, tous les messages de notification/statut/journal, et toute la narration des jeux sont entièrement traduits en anglais, français et arabe (avec une disposition de droite à gauche pour l'arabe) via un objet I18N intégré et des fonctions utilitaires tr()/trg() indexées par des attributs data-i18n. Le français est la langue par défaut. Un sélecteur à base de drapeaux se trouve dans l'en-tête ; le choix persiste dans localStorage.

Aide intégrée

Un bouton ❓ dans l'en-tête ouvre une fenêtre de référence rapide (Parler à ton robot, Nom & personnalité, Connecter un micro:bit, Commandes & jeux, Astuces), traduite comme le reste de l'interface. Se ferme via le bouton ×, la touche Échap, ou en cliquant en dehors de la carte.

Vie privée par conception : en mode Démo, rien ne quitte le navigateur. Dans tout autre mode IA, seuls tes messages tapés/parlés sont envoyés à l'API de ce fournisseur — réglages, nom du robot et historique de discussion restent uniquement dans localStorage.

Données & vie privée

  • Le mode Démo fonctionne entièrement hors ligne.
  • Les modes IA envoient tes messages aux serveurs du fournisseur sélectionné (Groq/Google/Cohere/Mistral/OpenRouter).
  • Réglages, nom/personnalité du robot, et historique de discussion sont stockés uniquement dans le localStorage du navigateur — rien n'est téléversé ailleurs.
  • Aucune analytique, aucun script de suivi.

Dépannage

SymptômeCause / solution
Le micro ou le Bluetooth ne fonctionnent pasNécessite Chrome ou Edge, et un contexte sécurisé (https:// ou localhost) — pas file:///.
Le nom du robot ne semble pas s'enregistrerCorrigé : le champ du nom s'enregistre désormais à chaque frappe avec une notification de confirmation, ceci ne devrait donc plus se reproduire sur les versions actuelles.
L'application reste bloquée en anglais après avoir choisi un autre drapeauVérifie que JavaScript n'est pas bloqué ; les boutons drapeaux appellent setLanguage(), qui mémorise aussi le choix dans localStorage.
Le micro:bit ne réagit pasReflashe avec le code depuis flash.html — assure-toi que l'extension bluetooth et « Aucun appairage requis » sont bien réglés dans MakeCode.
