Sharing Files Between Ubuntu & Windows 11

Network Setup
Ubuntu host192.168.1.78
Windows host192.168.1.54
OS (Ubuntu)22.04 LTS
OS (Windows)11 Pro
ProtocolSMB / CIFS
ScopeSame LAN

This article documents a step-by-step procedure for setting up bidirectional file sharing on a local network.

Contents
  1. Overview
  2. Share an Ubuntu folder to Windows
  3. Share a Windows folder to Ubuntu
  4. Browsing shares from each file manager
  5. Troubleshooting

Overview

Both machines were on the same local network (LAN), which is required for this setup (no port forwarding or VPN needed). Ubuntu (via Samba) and Windows (natively) both speak the SMB/CIFS protocol, so each OS can act as both a file server and a client to the other — no third-party software required.

Note: Replace the IP addresses, usernames, and share names below with your own machines' values.

Share an Ubuntu folder to Windows

Goal: make an Ubuntu folder (e.g. the home directory) show up as a network drive on Windows.

On Ubuntu — install & configure Samba

Install Samba (skip if already installed):

sudo apt-get update
sudo apt-get install -y samba

Add a share definition to /etc/samba/smb.conf:

sudo tee -a /etc/samba/smb.conf > /dev/null <<'EOF'

[home_abdelhak]
   comment = Abdelhak Home Folder
   path = /home/abdelhak
   browseable = yes
   read only = no
   guest ok = no
   valid users = abdelhak
   create mask = 0664
   directory mask = 0775
EOF

Set a Samba password for your Linux user (separate credential store from your login password):

sudo smbpasswd -a abdelhak

Restart the Samba services and allow it through the firewall:

sudo systemctl restart smbd nmbd
sudo ufw allow samba          # only if ufw is active

Make sure Samba starts automatically on boot:

sudo systemctl enable smbd nmbd

On Windows — connect to the share

Open Command Prompt or PowerShell and test the connection:

net use Z: \\192.168.1.78\home_abdelhak /user:abdelhak

Enter the Samba password when prompted.

Make the mapping permanent (survives reboot, auto-reconnects at login):

net use Z: /delete
net use Z: \\192.168.1.78\home_abdelhak /user:abdelhak /persistent:yes

Open File Explorer — the drive appears under "This PC" as home_abdelhak (Z:).

Known issue: If Explorer shows "impossible d'accéder" (can't access) but net use works fine, it's usually because the Windows network profile is set to Public instead of Private. Public profiles restrict SMB browsing in Explorer even though direct connections still work. Fix it under Settings → Network & Internet → your connection → Network profile type → Private.

Share a Windows folder to Ubuntu

Goal: mount a Windows folder (e.g. the user profile) as a local directory on Ubuntu.

On Windows — enable sharing

Confirm network discovery & file sharing are on: Settings → Network & Internet → Advanced network settings → Advanced sharing settings, toggle Network discovery and File and printer sharing to On for the Private profile.

Right-click the folder to share (e.g. C:\Users\Win10) → Properties → Sharing tab → Advanced Sharing. Check "Share this folder", give it a share name (e.g. Win10). Click Permissions → grant your user Full Control → OK → OK → Close.

Verify from PowerShell:

net share

On Ubuntu — mount the share

Install the CIFS client tools:

sudo apt-get install -y cifs-utils

Create a mount point and test-mount it:

sudo mkdir -p /mnt/win10share
sudo mount -t cifs //192.168.1.54/Win10 /mnt/win10share \
  -o username=Win10,uid=$(id -u),gid=$(id -g)

Enter the Windows account password when prompted, then confirm with:

ls /mnt/win10share

Make it permanent using a credentials file (safer than a plaintext password in /etc/fstab, which is world-readable):

sudo mkdir -p /etc/samba/creds
sudo nano /etc/samba/creds/win10share

Add:

username=Win10
password=YOUR_WINDOWS_PASSWORD

Lock down the file permissions:

sudo chmod 600 /etc/samba/creds/win10share

Add a permanent auto-mount entry to /etc/fstab:

echo "//192.168.1.54/Win10 /mnt/win10share cifs credentials=/etc/samba/creds/win10share,uid=$(id -u),gid=$(id -g),iocharset=utf8,x-systemd.automount,x-systemd.requires=network-online.target,_netdev 0 0" | sudo tee -a /etc/fstab

Reload and test:

sudo systemctl daemon-reload
sudo mount -a
ls /mnt/win10share
Why x-systemd.automount + _netdev? These options mount the share on-demand once the network is ready, instead of blocking boot if the Windows PC happens to be off or unreachable.

Browsing shares from each file manager

From Ubuntu (Nautilus / "Files")

Once mounted, browse it like any local folder: open Files, press Ctrl+L, type /mnt/win10share, press Enter. Optionally drag the folder into the sidebar to bookmark it.

Alternatively, connect live over the network without the fstab mount: press Ctrl+L and enter smb://192.168.1.54/Win10 — this prompts for credentials via a GUI dialog.

From Windows (File Explorer)

The mapped drive appears automatically under This PC once set up with /persistent:yes. You can also type the UNC path directly in the address bar: \\192.168.1.78\home_abdelhak.

Troubleshooting

SymptomLikely causeFix
Explorer can't browse the share, but net use works Network profile set to Public Switch to Private profile in Windows network settings
RDP connection "lost connection" immediately Port 3389 blocked by Windows Firewall, or RDP not actually enabled Check Firewall → allow Remote Desktop; confirm the toggle is On in Settings → System → Remote Desktop
Two RDP servers conflict on Ubuntu (xrdp vs. GNOME Remote Desktop) Both try to bind port 3389 Disable the unused one: sudo systemctl disable --now xrdp
mount.cifs: command not found Missing package sudo apt-get install -y cifs-utils
