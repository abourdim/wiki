Cet article couvre Talking Robot, un robot web sur une seule page qui prononce à voix haute le texte tapé, transcrit ce qu'il entend, anime 13 émotions, et peut envoyer des mots à un BBC micro:bit via Bluetooth — sans aucun fournisseur IA ni compte impliqué.

Aperçu

Talking Robot est le frère plus simple et plus ancien de Bit-Bot : pas de fournisseur IA, pas d'historique de discussion, pas de comptes — juste les API intégrées du navigateur Speech Synthesis (texte→voix) et Speech Recognition (voix→texte), un visage de robot SVG animé avec 13 émotions, et une liaison optionnelle BBC micro:bit via Web Bluetooth UART. Tout fonctionne côté client ; rien n'est jamais envoyé à un serveur.

L'application est répartie sur plusieurs fichiers plutôt qu'un seul : index.html (balisage + toute la logique de l'application en ligne), styles.css, et makecode.ts (le code source du firmware micro:bit compagnon), plus un flash.html autonome pour transférer ce firmware sur une carte.

Démarrage rapide

  1. Ouvre l'application en ligne dans Chrome ou Edge.
  2. Tape quelque chose dans la zone de texte et clique sur Parler — le robot parle et sa bouche s'anime.
  3. Clique sur Écouter, autorise le microphone, et parle — tes mots apparaissent dans la zone.

Étape par étape : cloner, flasher & tester

Amène une copie vierge du dépôt jusqu'à un robot pleinement fonctionnel — parole dans les deux sens et, en option, un micro:bit jumelé — sans rien supposer d'autre que Chrome ou Edge.

1. Cloner le dépôt

git clone https://github.com/abourdim/talking-robot.git
cd talking-robot

2. Servir le site en local

Aucune étape de build, mais Speech Recognition et Web Bluetooth refusent tous deux un simple chemin file:/// :

python3 -m http.server 8000

Ouvre http://localhost:8000 dans Chrome ou Edge.

3. Obtenir le firmware du micro:bit (optionnel)

Passe cette étape si tu veux seulement tester la parole. Sinon ouvre flash.html, appuie sur Copier le code micro:bit, colle-le dans l'onglet JavaScript d'un nouveau projet makecode.microbit.org, ajoute l'extension bluetooth, et flashe — ou utilise le raccourci « Ouvrir le projet MakeCode partagé » sur la même page pour sauter entièrement le copier-coller.

4. Tester Parler

Tape une phrase, choisis une voix sous Voix & Langue, clique sur Parler. Un test réussi joue l'audio et anime la bouche en synchronisation — aucun appel réseau n'est impliqué, donc ça fonctionne même hors ligne.

5. Tester Écouter

Clique sur Écouter, autorise le microphone, parle clairement. Le texte transcrit devrait apparaître dans la zone en une seconde ou deux.

6. Tester les émotions

Clique sur quelques-uns des 13 boutons d'émotion sous le robot et confirme que le visage change instantanément pour chacun.

7. Tester la connexion au micro:bit

Clique sur Connecter, choisis ta carte, puis tape un mot et clique sur Envoyer (ou laisse Envoi auto s'en charger). Regarde le panneau Journal : tu devrais voir une ligne BLE TX → N_mot suivie d'un accusé de réception OK N_mot renvoyé par le micro:bit.

Une base fonctionnelle ressemble à ceci : audio en sortie avec animation de la bouche, texte transcrit en entrée, les 13 visages qui changent au clic, et une paire TX/ACK correspondante dans le journal après avoir connecté un micro:bit.

Comprendre le code (pour débutants)

Pour quiconque a l'application en marche et veut ouvrir index.html pour commencer à modifier quelque chose. Suppose des bases en JavaScript mais rien de spécifique à ce code. À sauter si tu veux seulement utiliser l'application.

La forme du fichier

Toute la logique de l'application vit en ligne dans index.html, enveloppée dans une seule fonction auto-exécutée — (() => { ... })(); — de sorte que rien de ce qu'elle déclare ne fuit dans la portée globale sauf les deux choses explicitement attachées à window pour être utilisées par les attributs onclick en ligne : setUILanguage et toggleHelp. Tout le reste (parler, écouter, BLE, émotions) est une simple fonction à l'intérieur de cette fermeture, câblée en bas avec des appels addEventListener plutôt que des gestionnaires en ligne.

Le système de traduction : I18N → tr() → data-i18n

Même schéma que Bit-Bot : un objet I18N indexé par langue puis par clé de chaîne, une recherche tr(key) avec repli sur l'anglais, et une variante trg(key, vars) qui substitue des jetons {placeholder} pour les valeurs dynamiques (noms de voix, messages d'erreur, compteurs). Le balisage statique est marqué data-i18n="btn_speak" ; un petit nombre d'éléments qui ont besoin de balisage <b>/<br> intégré (comme le texte d'astuce BLE) utilisent plutôt data-i18n-html, qui fixe innerHTML plutôt que textContent. applyLang(lang) parcourt les deux ensembles d'attributs, bascule document.documentElement.dir en rtl pour l'arabe, et redérive chaque morceau de texte d'interface dynamique (pastille de statut, libellé du bouton micro, badge de connexion) à partir des mêmes variables d'état qui l'ont piloté à l'origine — donc changer de langue en cours de session ne laisse jamais d'anglais périmé derrière.

Comment fonctionne Parler : texte → voix → bouche

  clic sur Parler
       │
       ▼
  speak()  ──▶  new SpeechSynthesisUtterance(text)
       │                 · Voix aléatoire cochée ? choisit une voix correspondante
       │                 · sinon : utilise la voix sélectionnée dans la liste
       │                 · sinon, si la langue est l'arabe : force la première
       │                   voix arabe trouvée (repli avec avertissement dans le
       │                   journal si aucune n'est installée)
       ▼
  speechSynthesis.speak(u)
       │
       ├─ u.onstart  ──▶  boucle animateMouth() (hauteur/échelle aléatoire par image)
       └─ u.onend    ──▶  resetMouth()  +  autoSendToMicrobit('speak')

Le repli de voix arabe existe parce que la plupart des systèmes d'exploitation de bureau livrent bien moins de voix TTS arabes que anglaises/françaises par défaut — l'application vérifie activement cela au chargement et journalise une astuce spécifique « installe une voix arabe » plutôt que de parler silencieusement dans la mauvaise langue.

Comment fonctionne Écouter : micro → texte → (optionnel) BLE

listen() crée une instance SpeechRecognition et, selon la case Écoute continue, règle rec.continuous/rec.interimResults en conséquence. Chaque événement de résultat parcourt event.results à partir de resultIndex, gardant la dernière transcription provisoire séparée de tout ce qui est marqué isFinal ; en mode continu, seul un résultat final déclenche autoSendToMicrobit(), donc les sous-titres provisoires en direct n'inondent pas le micro:bit en milieu de phrase. Si Parole automatique est activée, le texte entendu est reprononcé via speak() à la place, qui envoie au micro:bit lui-même une fois cette énonciation terminée.

Parler au micro:bit : bleConnect() et jetons syllabiques

bleConnect() appelle navigator.bluetooth.requestDevice() filtré sur les appareils nommés BBC micro:bit, puis découvre les caractéristiques d'écriture et de notification du service Nordic UART directement par leurs propriétés plutôt que des UUID fixes (donc ça tolère de petites différences de firmware). Chaque envoi passe par tokensFromInput(), qui découpe le texte en mots et étiquette chacun avec un compte approximatif de syllabes depuis countSyllables() — par exemple "elephant" devient "3_elephant" — puis bleWriteLine() envoie chaque jeton comme sa propre ligne, découpée en blocs de 20 octets à la fois car BLE UART a une petite limite par écriture. Le micro:bit renvoie chacun préfixé par OK, visible dans le Journal via le gestionnaire characteristicvaluechanged de la caractéristique de notification.

Architecture du système, illustrée

                        ┌───────────────────────────┐
                        │    index.html (browser)   │
  ⌨ type + Speak   ────▶│  speak()                  │
                        │    │  Web Speech Synthesis │
                        │    ▼  (on-device, no server)
                        │  🔊 audio + mouth anim     │
                        │                            │
  🎤 mic + Listen  ────▶│  listen()                 │
                        │    │  Web Speech Recognition│
                        │    ▼  (on-device, no server)
                        │  text box filled           │
                        │       │                    │
                        │       ▼                    │
   BBC micro:bit    ◀──▶│  bleConnect()/bleWriteLine()│
   (Bluetooth LE)       └───────────────────────────┘

Contrairement à Bit-Bot, rien ici ne fait appel à un serveur distant — Speech Synthesis et Speech Recognition sont toutes deux intégrées au navigateur et fonctionnent entièrement sur l'appareil. Le seul trafic réseau sortant que cette application génère jamais est la liaison Bluetooth vers le micro:bit, qui n'est pas du « réseau » au sens internet du terme.

La disposition HTML, illustrée

  <body>

       ├─ #helpOverlay      fenêtre de référence rapide ❓

Il n'y a pas de panneau de réglages ou de superposition d'intégration comme Bit-Bot — chaque contrôle est visible sur la page en même temps, en deux colonnes, ce qui explique pourquoi cette application sœur semble « plus simple » : moins de choses sont cachées derrière des menus.

Le firmware du micro:bit : makecode.ts

Là où le firmware de Bit-Bot attend un vocabulaire unique et fixe de commandes d'un mot, le tour de force de ce firmware est de comprendre des phrases ordinaires en anglais ou en français, en plus de l'ancien protocole EMO: dont il est issu — utile car l'application web transmet exactement ce que tu as tapé ou dit, pas un mot de commande pré-choisi.

Réduire une phrase à quelque chose de comparable

normalizeText() met la ligne en minuscules et remplace chaque caractère qui n'est pas a–z, un chiffre, ou un espace par un espace — ce qui permet à "J'ai peur!" et "jai peur" de correspondre au même mot-clé malgré l'apostrophe et l'orthographe voisine des accents :

function normalizeText(s: string): string {
    let t = s.toLowerCase()
    let out = ""
    for (let i = 0; i < t.length; i++) {
        let c = t.charCodeAt(i)
        if (c == 32) { out += " "; continue }        // space
        if (c >= 97 && c <= 122) { out += t.charAt(i); continue }  // a-z
        if (c >= 48 && c <= 57) { out += t.charAt(i); continue }   // 0-9
        out += " "                                    // anything else → space
    }
    while (out.indexOf("  ") >= 0) out = out.split("  ").join(" ")
    return out.trim()
}
function hasWord(t: string, w: string): boolean {
    return (" " + t + " ").indexOf(" " + w + " ") >= 0   // whole-word match, not substring
}

hasWord() ajoute des espaces des deux côtés avant de chercher, précisément pour que la correspondance avec "sad" ne se déclenche pas aussi sur "sadly" ou "embassador" — un petit bug facile à introduire si tu ajoutes toi-même un mot-clé un jour.

Tables de mots-clés bilingues

detectEmotion() et detectDirection() sont toutes deux de simples listes ordonnées de vérifications hasWord(), mots-clés anglais et français côte à côte, la première correspondance gagne :

FonctionRetourneCorrespondances (EN / FR)
detectEmotion()happyhappy, joy, content / heureux
sadsad / triste
sillysilly, funny / rigolo, bete
scaredscared, afraid / peur
(+ angry, surprised, sleepy, laugh, party, robot)…
detectDirection()upup, forward / haut, monte, avance
stopstop / arrete, arret
(+ down, left, right, spin)…

Une troisième fonction, funEffects(), superpose des easter eggs sans affecter du tout le résultat émotion/direction — dire « banana » joue deux notes et affiche un visage rigolo, « boom » fait clignoter un damier avec un ton grave, « dance »/« danse » alterne des icônes de cœur.

Le gestionnaire : la direction gagne, puis l'émotion, puis toujours un ACK

function handleLine(line: string) {
    line = line.trim()
    if (line.length == 0) return

    if (line.indexOf("EMO:") == 0) {          // explicit protocol, unchanged
        showEmotion(line.substr(4).trim())
        bluetooth.uartWriteLine("OK " + line)
        return
    }

    let d = detectDirection(line)
    if (d.length > 0) { showDirection(d); bluetooth.uartWriteLine("OK " + line); return }

    let e = detectEmotion(line)
    if (e.length > 0) showEmotion(e)

    funEffects(line)
    bluetooth.uartWriteLine("OK " + line)     // every line gets an ACK, matched or not
}

La direction est vérifiée avant l'émotion et retourne immédiatement si trouvée — une phrase ne peut pas être à la fois « va à gauche » et « content » sur la même ligne en ce qui concerne l'affichage LED, la direction a la priorité. De façon cruciale, la toute dernière ligne se déclenche toujours : même une phrase qui ne correspond à rien du tout reçoit quand même "OK " + line renvoyé en écho, ce que le panneau Journal du navigateur utilise pour confirmer que chaque mot a fait l'aller-retour, correspondant ou non.

L'aller-retour complet

  browser: bleWriteLine("3_scared")
       │
       ▼  bluetooth write (UART RX characteristic)
  micro:bit: onUartDataReceived → handleLine("3_scared")
       │
       ├─ not "EMO:"           → skip
       ├─ detectDirection() → ""  → no direction keyword found
       ├─ detectEmotion()   → "scared"  → showEmotion("scared")
       ├─ funEffects()      → no easter-egg word found
       ▼
  bluetooth.uartWriteLine("OK 3_scared")
       │
       ▼  bluetooth notify (UART TX characteristic)
  browser: characteristicvaluechanged → logLine("micro:bit: OK 3_scared")

Le faire parler

Tape du texte, choisis une langue et une voix sous Voix & Langue, puis clique sur Parler (ou appuie sur Ctrl/Cmd+Entrée). Les curseurs de vitesse et de hauteur ajustent la diction ; une option Voix aléatoire à chaque parole choisit une voix installée différente à chaque fois pour varier.

Le faire écouter

Clique sur Écouter et autorise le microphone. Deux modes :

  • Coup unique (par défaut) — capture une seule énonciation, puis s'arrête.
  • Écoute continue (mains libres) — redémarre automatiquement après chaque phrase, affichant le texte provisoire en direct pendant que tu parles.

Parole automatique après écoute fait immédiatement répéter au robot ce qu'il a entendu.

Émotions

Treize boutons d'émotion sous le visage du robot — Neutre, Content, Triste, Fâché, Très fâché, Surpris, Rire, Rigolo, Effrayé, Fête, Robot, Intello, Endormi — chacun échange instantanément l'état CSS des yeux/sourcils/bouche/joues. Si un micro:bit est connecté, la même émotion lui est envoyée comme commande EMO:<nom>.

Connecter un micro:bit

Clique sur Connecter sous BLE micro:bit (UART) et choisis ta carte. Une fois jumelé, le robot envoie automatiquement chaque mot parlé/tapé/entendu au micro:bit sous forme d'un jeton par ligne, étiqueté avec un compte de syllabes (ex. 3_elephant), et le micro:bit accuse réception de chacun avec OK 3_elephant renvoyé sur la même liaison UART — visible dans le Journal sur la page.

Écouter et Bluetooth nécessitent tous deux un contexte sécurisé : https:// ou localhost, pas une simple page file:///.

Obtenir le code du firmware

flash.html récupère le makecode.ts actuel et l'affiche avec un bouton Copier le code micro:bit en un tap, plus les étapes pour le coller dans makecode.microbit.org, ajouter l'extension bluetooth, et flasher. Elle renvoie aussi directement vers un projet MakeCode partagé déjà programmé pour qui préfère sauter entièrement le copier-coller. Elle est reliée depuis un bouton Obtenir le code du firmware sous Liens du projet sur la page principale.

Langues & système de traduction

Contrairement à Bit-Bot, cette application n'avait à l'origine aucune traduction de l'interface — seule la liste déroulante de langue vocale était multilingue. Elle possède désormais un objet I18N complet (anglais/français/arabe) avec un sélecteur à base de drapeaux dans l'en-tête, couvrant chaque bouton, carte, astuce, et les ~50 messages dynamiques de journal/statut, avec une disposition de droite à gauche pour l'arabe. Le choix de langue est stocké sous sa propre clé localStorage, séparée de celle de Bit-Bot, puisque les deux applications partagent l'origine abourdim.github.io.

Aide intégrée

Un bouton ❓ dans l'en-tête ouvre une fenêtre couvrant Le faire parler, Le faire écouter, Changer les émotions, Connecter un micro:bit, et Astuces — traduite comme le reste de l'interface, fermable via × / Échap / clic en dehors.

Dépannage

SymptômeCause / solution
Écouter ne fait rienUtilise Chrome/Edge, autorise le microphone, et ouvre via http://localhost ou https:// — pas file:///.
Aucune voix arabe disponibleLe système d'exploitation a besoin d'une voix de synthèse vocale arabe installée ; l'application journalise un avertissement spécifique et se replie sur une autre voix si aucune n'est trouvée.
La connexion Bluetooth échoueNécessite HTTPS/localhost et un navigateur avec Web Bluetooth (Chrome/Edge). Le micro:bit doit annoncer sa présence et être à portée.
Le micro:bit n'envoie jamais d'ACKReflashe avec le code actuel depuis flash.html et assure-toi que l'extension bluetooth est ajoutée dans MakeCode.
