This article covers Talking Robot, a single-page web robot that speaks typed text out loud, transcribes what it hears, animates 13 emotions, and can send words to a BBC micro:bit over Bluetooth — with no AI provider or account involved.

Overview

Talking Robot is the simpler, earlier sibling of Bit-Bot: no AI provider, no chat history, no accounts — just the browser's built-in Speech Synthesis (text→voice) and Speech Recognition (voice→text) APIs, an animated SVG robot face with 13 emotions, and an optional BBC micro:bit link over Web Bluetooth UART. Everything runs client-side; nothing is ever sent to a server.

The app is spread across a few files rather than one: index.html (markup + all app logic inline), styles.css, and makecode.ts (the companion micro:bit firmware source), plus a standalone flash.html for getting that firmware onto a board.

Quick start

  1. Open the live app in Chrome or Edge.
  2. Type something in the text box and click Speak — the robot talks and its mouth animates.
  3. Click Listen, allow the microphone, and talk — your words appear in the box.

Step-by-step: clone, flash & test

Takes a bare checkout to a fully working robot — speech in both directions and, optionally, a paired micro:bit — assuming nothing beyond Chrome or Edge.

1. Clone the repository

git clone https://github.com/abourdim/talking-robot.git
cd talking-robot

2. Serve it locally

No build step, but Speech Recognition and Web Bluetooth both refuse a bare file:/// path:

python3 -m http.server 8000

Open http://localhost:8000 in Chrome or Edge.

3. Get the micro:bit firmware (optional)

Skip this if you only want to test speech. Otherwise open flash.html, tap Copy micro:bit Code, paste into a new makecode.microbit.org project's JavaScript tab, add the bluetooth extension, and flash — or use the "Open shared MakeCode project" shortcut on the same page to skip the copy-paste entirely.

4. Test Speak

Type a sentence, pick a voice under Voice & Language, click Speak. A healthy run plays audio and animates the mouth in sync — no network call is involved, so this works even offline.

5. Test Listen

Click Listen, allow the microphone, speak clearly. The transcribed text should appear in the box within a second or two.

6. Test emotions

Click through a few of the 13 emotion buttons under the robot and confirm the face changes instantly for each.

7. Test the micro:bit connection

Click Connect, pick your board, then type a word and click Send (or just let Auto send handle it). Watch the Log panel: you should see a BLE TX → N_word line followed by an OK N_word acknowledgement echoed back from the micro:bit.

A working baseline looks like: audio out with mouth animation, transcribed text in, all 13 faces changing on click, and a matching TX/ACK pair in the Log after connecting a micro:bit.

Understanding the code (for newbies)

For anyone with the app running who wants to open index.html and start changing something. Assumes basic JavaScript but nothing about this codebase specifically. Skip it if you only want to use the app.

The shape of the file

All app logic lives inline in index.html, wrapped in a single self-executing function — (() => { ... })(); — so nothing it declares leaks into the global scope except the two things explicitly attached to window for use by inline onclick attributes: setUILanguage and toggleHelp. Everything else (speak, listen, BLE, emotions) is a plain function inside that closure, wired up at the bottom with addEventListener calls rather than inline handlers.

The translation system: I18N → tr() → data-i18n

Same pattern as Bit-Bot: an I18N object keyed by language then by string key, a tr(key) lookup with English fallback, and a trg(key, vars) variant that substitutes {placeholder} tokens for dynamic values (voice names, error messages, counts). Static markup is tagged data-i18n="btn_speak"; a small number of elements that need embedded <b>/<br> markup (like the BLE hint text) use data-i18n-html instead, which sets innerHTML rather than textContent. applyLang(lang) walks both attribute sets, flips document.documentElement.dir to rtl for Arabic, and re-derives every piece of dynamic UI text (status pill, mic button label, connection badge) from the same state variables that drove it originally — so switching language mid-session never leaves stale English behind.

How Speak works: text → voice → mouth

  click Speak
       │
       ▼
  speak()  ──▶  new SpeechSynthesisUtterance(text)
       │                 · Random voice checked? pick any matching voice
       │                 · else: use the selected dropdown voice
       │                 · else, if language is Arabic: force the first
       │                   Arabic voice found (falls back with a log
       │                   warning if none is installed)
       ▼
  speechSynthesis.speak(u)
       │
       ├─ u.onstart  ──▶  animateMouth() loop (random height/scale per frame)
       └─ u.onend    ──▶  resetMouth()  +  autoSendToMicrobit('speak')

The Arabic-voice fallback exists because most desktop OSes ship with far fewer Arabic TTS voices than English/French ones installed by default — the app actively checks for this on load and logs a specific "install an Arabic voice" hint rather than silently speaking in the wrong language.

How Listen works: mic → text → (optional) BLE

listen() creates a SpeechRecognition instance and, depending on the Continuous listening checkbox, sets rec.continuous/rec.interimResults accordingly. Every result event walks event.results from resultIndex onward, keeping the latest interim transcript separate from anything marked isFinal; in continuous mode only a final result triggers autoSendToMicrobit(), so live interim captions don't spam the micro:bit mid-sentence. If Auto speak is on, the heard text is spoken back via speak() instead, which sends to the micro:bit itself once that utterance ends.

Talking to the micro:bit: bleConnect() and syllable tokens

bleConnect() calls navigator.bluetooth.requestDevice() filtered to devices named BBC micro:bit, then discovers the Nordic UART service's write and notify characteristics directly by their properties rather than fixed UUIDs (so it tolerates minor firmware differences). Every send goes through tokensFromInput(), which splits the text into words and tags each with a rough syllable count from countSyllables() — e.g. "elephant" becomes "3_elephant" — then bleWriteLine() sends each token as its own line, chunked to 20 bytes at a time because BLE UART has a small per-write limit. The micro:bit echoes each one back prefixed OK, visible in the Log via the notify characteristic's characteristicvaluechanged handler.

Unlike Bit-Bot, nothing here calls out to a remote server — Speech Synthesis and Speech Recognition are both built into the browser and run entirely on-device. The only outbound network traffic this app ever generates is the Bluetooth link to the micro:bit, which isn't "network" in the internet sense at all.

The micro:bit firmware: makecode.ts

Where Bit-Bot's firmware expects a single fixed vocabulary of one-word commands, this firmware's whole trick is understanding plain sentences in English or French, in addition to the older EMO: protocol it grew from — useful because the web app streams whatever you actually typed or said, not a pre-picked command word.

Stripping a sentence down to something matchable

normalizeText() lowercases the line and replaces every character that isn't a–z, a digit, or a space with a space — which is what lets "J'ai peur!" and "jai peur" match the same keyword despite the apostrophe and accent-adjacent spelling:

function normalizeText(s: string): string {
    let t = s.toLowerCase()
    let out = ""
    for (let i = 0; i < t.length; i++) {
        let c = t.charCodeAt(i)
        if (c == 32) { out += " "; continue }        // space
        if (c >= 97 && c <= 122) { out += t.charAt(i); continue }  // a-z
        if (c >= 48 && c <= 57) { out += t.charAt(i); continue }   // 0-9
        out += " "                                    // anything else → space
    }
    while (out.indexOf("  ") >= 0) out = out.split("  ").join(" ")
    return out.trim()
}
function hasWord(t: string, w: string): boolean {
    return (" " + t + " ").indexOf(" " + w + " ") >= 0   // whole-word match, not substring
}

hasWord() pads both sides with spaces before searching, specifically so matching "sad" doesn't also fire on "sadly" or "embassador" — a small but easy bug to introduce if you ever add a keyword yourself.

Bilingual keyword tables

detectEmotion() and detectDirection() are both just ordered lists of hasWord() checks, English and French keywords side by side, first match wins:

FunctionReturnsMatches (EN / FR)
detectEmotion()happyhappy, joy, content / heureux
sadsad / triste
sillysilly, funny / rigolo, bete
scaredscared, afraid / peur
(+ angry, surprised, sleepy, laugh, party, robot)…
detectDirection()upup, forward / haut, monte, avance
stopstop / arrete, arret
(+ down, left, right, spin)…

A third function, funEffects(), layers Easter eggs on top without affecting the emotion/direction result at all — saying "banana" plays two notes and shows a silly face, "boom" flashes a checkerboard with a low tone, "dance"/"danse" alternates heart icons.

The handler: direction wins, then emotion, then always ACK

function handleLine(line: string) {
    line = line.trim()
    if (line.length == 0) return

    if (line.indexOf("EMO:") == 0) {          // explicit protocol, unchanged
        showEmotion(line.substr(4).trim())
        bluetooth.uartWriteLine("OK " + line)
        return
    }

    let d = detectDirection(line)
    if (d.length > 0) { showDirection(d); bluetooth.uartWriteLine("OK " + line); return }

    let e = detectEmotion(line)
    if (e.length > 0) showEmotion(e)

    funEffects(line)
    bluetooth.uartWriteLine("OK " + line)     // every line gets an ACK, matched or not
}

Direction is checked before emotion and returns immediately if found — a sentence can't be both "go left" and "happy" on the same line as far as the LED display is concerned, direction takes priority. Critically, the very last line always fires: even a sentence matching nothing at all still gets "OK " + line echoed back, which is what the browser's Log panel uses to confirm every single word made the round trip, matched or not.

The full round trip

  browser: bleWriteLine("3_scared")
       │
       ▼  bluetooth write (UART RX characteristic)
  micro:bit: onUartDataReceived → handleLine("3_scared")
       │
       ├─ not "EMO:"           → skip
       ├─ detectDirection() → ""  → no direction keyword found
       ├─ detectEmotion()   → "scared"  → showEmotion("scared")
       ├─ funEffects()      → no easter-egg word found
       ▼
  bluetooth.uartWriteLine("OK 3_scared")
       │
       ▼  bluetooth notify (UART TX characteristic)
  browser: characteristicvaluechanged → logLine("micro:bit: OK 3_scared")

Make it talk

Type text, pick a language and a voice under Voice & Language, then click Speak (or press Ctrl/Cmd+Enter). Rate and pitch sliders adjust delivery; a Random voice each speak option picks a different installed voice every time for variety.

Make it listen

Click Listen and allow the microphone. Two modes:

  • Single-shot (default) — captures one utterance, then stops.
  • Continuous listening (hands-free) — keeps restarting automatically after each phrase, showing interim text live as you talk.

Auto speak after listening makes the robot immediately repeat back what it heard.

Emotions

Thirteen emotion buttons under the robot face — Neutral, Happy, Sad, Angry, Angry+, Surprised, Laugh, Silly, Scared, Party, Robot, Nerdy, Sleepy — each instantly swap the eyes/eyebrows/mouth/cheeks CSS state. If a micro:bit is connected, the same emotion is sent to it as an EMO:<name> command.

Connecting a micro:bit

Click Connect under BLE micro:bit (UART) and pick your board. Once paired, the robot automatically sends every spoken/typed/heard word to the micro:bit as one token per line, tagged with a syllable count (e.g. 3_elephant), and the micro:bit acknowledges each with OK 3_elephant back over the same UART link — visible in the on-page Log.

Listen and Bluetooth both require a secure context: https:// or localhost, not a bare file:/// page.

Getting the firmware code

flash.html fetches the current makecode.ts and shows it with a one-tap Copy micro:bit Code button, plus the steps to paste it into makecode.microbit.org, add the bluetooth extension, and flash. It also links straight to an already-programmed shared MakeCode project for anyone who'd rather skip the copy-paste entirely. It's linked from a Get Firmware Code button under Project Links on the main page.

Languages & translation system

Unlike Bit-Bot, this app originally had no UI translation at all — only the speech language dropdown was multilingual. It now has a full I18N object (English/French/Arabic) with a flag-based switcher in the header, covering every button, card, hint, and the ~50 dynamic log/status messages, with right-to-left layout for Arabic. The language choice is stored under its own localStorage key, separate from Bit-Bot's, since both apps share the abourdim.github.io origin.

In-app Help

A ❓ button in the header opens a modal covering Make it talk, Make it listen, Change emotions, Connect a micro:bit, and Tips — translated the same as the rest of the UI, closable via × / Escape / clicking outside.

Troubleshooting

SymptomCause / fix
Listen does nothingUse Chrome/Edge, allow the microphone, and open via http://localhost or https:// — not file:///.
No Arabic voice availableThe OS needs an Arabic text-to-speech voice installed; the app logs a specific warning and falls back to another voice if none is found.
Bluetooth connect failsNeeds HTTPS/localhost and a browser with Web Bluetooth (Chrome/Edge). The micro:bit must be advertising and in range.
micro:bit never sends an ACKReflash with the current code from flash.html and make sure the bluetooth extension is added in MakeCode.
