WDIY Robot — version RemoteXY d'origine (esp32c3_super_mini_robot_remotexy)

WDIY Robot (RemoteXY)
CarteESP32-C3 Super Mini (RISC-V, USB-CDC natif)
ChâssisTraction différentielle 2 roues, servomoteurs à rotation continue
ContrôleAppli RemoteXY (iOS/Android/bureau), mode BLE
Système de buildPlatformIO
Bibliothèque BLEBibliothèque Arduino officielle RemoteXY
Dépôtgithub.com/abourdim/esp32c3_super_mini_robot_remotexy (renommé depuis esp32c3_super_mini_robot)
SuccesseurWDIY Robot (bit-rxy) — même matériel, converti vers un contrôle BLE gratuit

Cet article couvre esp32c3_super_mini_robot_remotexy, le firmware d'origine de ce robot à traction différentielle ESP32-C3 : piloté via Bluetooth Low Energy par l'application commerciale RemoteXY, en utilisant l'éditeur visuel et la bibliothèque Arduino propres à RemoteXY. Il précède la conversion bit-rxy couverte dans l'article jumeau et n'y a pas été touché — les deux sont des dépôts séparés avec des couches de contrôle séparées, sur la même conception matérielle.

Pourquoi ce dépôt existe encore, inchangé : lorsque le robot a été converti pour parler le protocole BLE gratuit et ouvert de bit-rxy, la version RemoteXY a délibérément été laissée intacte dans son propre dépôt plutôt que modifiée sur place — voir WDIY Robot (bit-rxy) pour le raisonnement et le successeur activement développé. Cet article documente l'original comme version historique/de référence, et pour quiconque possède déjà une licence RemoteXY et la préfère.

Aperçu

RemoteXY est une plateforme commerciale de télécommande : un éditeur GUI par glisser-déposer (sur le web) permet de concevoir un panneau de contrôle — joysticks, boutons, jauges — qui se compile en un blob de configuration binaire intégré directement dans le firmware. La bibliothèque Arduino officielle de RemoteXY gère ensuite le transport Bluetooth et le protocole, et l'application mobile/bureau RemoteXY affiche la disposition annoncée par le firmware.

Le panneau de contrôle de ce robot est un joystick unique (direction), un bouton klaxon, et trois sorties en lecture seule (distance, vitesse, batterie) plus une barre circulaire et des événements sonores — le même ensemble de fonctionnalités que la conversion bit-rxy a plus tard reproduit depuis zéro sur un protocole différent et gratuit.

Démarrage rapide

git clone https://github.com/abourdim/esp32c3_super_mini_robot_remotexy.git
cd esp32c3_super_mini_robot_remotexy/01_software/01_app
./launch.sh flash

Installez l'application RemoteXY (App Store iOS / Google Play / bureau), ouvrez-la, et connectez-vous via Bluetooth à diy_app_b3. L'application affiche automatiquement la disposition joystick/bouton/jauges — aucun code d'appairage nécessaire au-delà du flux de connexion propre à RemoteXY.

Les particularités de l'USB-CDC natif ne sont pas contournées ici. Contrairement au fork bit-rxy, le platformio.ini de ce dépôt n'épingle pas upload_speed/upload_flags pour le point de terminaison USB-CDC natif de l'ESP32-C3 (suivi comme le BUG-005 toujours ouvert dans le propre traqueur de bugs de ce dépôt). Si les téléversements échouent avec « No serial data received » ou « Unable to verify flash chip connection », voir Dépannage.

Comprendre le code

Toute la couche de contrôle RemoteXY vit dans 03_remotexy.cpp/.h, structurée très différemment d'un protocole BLE écrit à la main :

#define REMOTEXY_MODE__ESP32CORE_BLE
#include <BLEDevice.h>
#define REMOTEXY_BLUETOOTH_NAME CONFIG_REMOTEXY_BLUETOOTH_NAME
#include <RemoteXY.h>

uint8_t RemoteXY_CONF[] =   // 176 octets
  { 255,3,0,15,0,169,0,19,0,0,0,0,179,2,130,200,108,200,1,1, ... };

struct {
  int8_t  joystick_01_x;   // -100..100
  int8_t  joystick_01_y;   // -100..100
  uint8_t button_01;       // 1 = appuyé
  float   onlineGraph_01_distance;
  float   onlineGraph_02_speed;
  float   onlineGraph_03_battery;
  int8_t  circularBar_01;  // 0..100
  int16_t sound_01;        // 0 = aucun, sinon une constante d'ID sonore
  uint8_t connect_flag;
} RemoteXY;

Deux choses ressortent par rapport à un protocole écrit à la main comme celui de bit-rxy :

  • RemoteXY_CONF[] est un octet opaque et généré — la disposition GUI réelle (position du joystick, taille du bouton, plages des jauges, étiquettes) est encodée dans ce tableau par l'éditeur en ligne de RemoteXY, et non modifiable à la main dans le code source. Changer la disposition signifie ouvrir le projet dans l'éditeur, le reconcevoir là-bas, et réexporter le code généré — il n'y a pas d'équivalent local au flux de travail JSON-lisible-en-commentaire/layout_cfg.sh de bit-rxy.
  • RemoteXY est une simple structure globale, pas un protocole de messages à analyser — RemoteXY_Handler() de la bibliothèque (appelé à chaque loop()) gère tout le trafic BLE en interne et garde simplement les champs de cette structure synchronisés avec ce que l'application affiche. Le code du firmware ne voit jamais d'octets bruts ; il lit/écrit simplement des champs de structure, par exemple remotexy_get_joystick_01_x() est un simple wrapper d'une ligne retournant RemoteXY.joystick_01_x.

Tout ce qui suit — le mixage arcade joystick-vers-servo de 04_tasks.cpp, le switch d'ID sonore, le code OLED/batterie/ultrason — est identique dans l'esprit à ce que le fork bit-rxy a conservé (les noms de fonctions du fork ont été délibérément préservés pour correspondre à l'API de ce fichier, afin que le portage du transport n'ait jamais nécessité de toucher à cette logique).

La limitation de licence RemoteXY (BUG-004)

Le palier gratuit de RemoteXY plafonne un projet à 5 éléments GUI par interface. Le panneau de ce robot — joystick, bouton, 3 jauges/graphiques, une barre circulaire — se situe exactement à ou au-dessus de ce plafond selon la façon dont les éléments sont comptés, ce qui est précisément la friction qui a motivé la conversion bit-rxy : bit-rxy n'a aucun plafond de ce type, aucun palier payant, et est entièrement open-source.

C'est la raison sous-jacente pour laquelle le projet jumeau existe tout court — pas un bug dans le code, mais une contrainte de licence de la plateforme dont dépend ce dépôt.

Référence matérielle

Matériel/brochage identique à la version bit-rxy, puisque c'est la même conception physique de robot — voir WDIY Robot (bit-rxy) — Référence matérielle pour le tableau GPIO complet. Les deux dépôts partagent CONFIG_SERVO_SPEED_STOP_LEFT/_RIGHT = 90° avec de petites corrections _OFFSET, et le même nom d'appareil BLE, diy_app_b3.

Dépannage

SymptômeCause / solution
Le téléversement échoue avec « No serial data received » ou « Unable to verify flash chip connection »Le platformio.ini de ce dépôt n'épingle pas upload_speed/upload_flags pour les particularités de l'USB-CDC natif de l'ESP32-C3 (BUG-005, toujours ouvert ici). Réessayez plusieurs fois, ou empruntez la correction du platformio.ini du fork bit-rxy : upload_speed = 115200 + upload_flags = --no-stub.
L'application RemoteXY dit que l'interface nécessite une licence PRO / certains éléments sont grisésAttendu — voir la limitation de licence ci-dessus. Achetez une licence RemoteXY PRO, réduisez la disposition GUI dans l'éditeur de RemoteXY pour tenir dans le plafond gratuit de 5 éléments, ou passez au fork bit-rxy gratuit à la place.
Vous voulez changer la disposition de contrôle (ajouter un widget, déplacer le joystick)Impossible en modifiant 03_remotexy.cpp directement — la disposition est générée par l'éditeur en ligne de RemoteXY. Reconcevez-la là-bas et réexportez le code RemoteXY_CONF[]/structure généré.
La carte se réinitialise en mode téléchargement ROM de manière inattendueGPIO 9 est aussi la broche de strapping BOOT du C3 sur certaines variantes de carte — évitez de câbler quoi que ce soit qui pourrait la tirer à l'état bas pendant la mise sous tension/réinitialisation.
