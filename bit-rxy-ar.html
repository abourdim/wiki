امسح هذا الرمز بالهاتف لفتح التطبيق مباشرة. لا شيء لتثبيته — يعمل داخل المتصفح.

تتناول هذه المقالة rxy (Micro:bit Remote Builder)، أداة بدون برمجة تعتمد على السحب والإفلات لتصميم أجهزة تحكم بلوتوث مخصصة لـ BBC micro:bit — وهي فريدة في هذه المجموعة من التطبيقات لأنها تولّد فيرموير MakeCode الخاص بها فوريًا، ولأنها قادرة على تحميل هذا الفيرموير مباشرة من المتصفح عبر البلوتوث.

أما خَلَفُها — الذي يعكس المنهج فيترك الروبوت نفسه يرسل واجهته، أيًّا كان الروبوت — فانظر rxy-web.

نظرة عامة

bit-rxy يتيح لك تصميم جهاز تحكم بلوتوث مخصص — أزرار، منزلقات، عصي تحكم، مقاييس، أيًا كان ما تحتاجه — بسحب الأدوات إلى لوحة، ثم يولّد فيرموير MakeCode المطابق تلقائيًا. على عكس Bit-Bot وTalking Robot وmicro:bit Playground (التي تستخدم جميعها بروتوكول فيرموير ثابت)، هنا يتم توليد البروتوكول نفسه حسب التصميم: كل أداة تضعها تصبح كتلة معالجة في الكود المُصدَّر، ويُدمَج التخطيط بأكمله في الفيرموير كسلسلة Base64 حتى يتمكن الـ micro:bit من إعادة إرسال إعداداته الخاصة لأي تطبيق يطلبها.

كما يذهب أبعد من التطبيقات الأخرى في هذه المجموعة: بدلًا من الاكتفاء بـ«انسخ هذا الكود إلى MakeCode»، يمكنه تجميع الكود المولَّد وتحميله مباشرة إلى اللوحة من المتصفح، إما عبر البلوتوث (باستخدام خدمة التحميل الجزئي المدمجة في الـ micro:bit) أو عبر WebUSB.

البدء السريع

  1. افتح التطبيق المباشر في Chrome أو Edge.
  2. في تبويب ✏️ بناء، اسحب الأدوات إلى اللوحة (أو ابدأ من قالب جاهز).
  3. اضغط 📄 الكود، انسخ كود MakeCode المولَّد، الصقه في makecode.microbit.org، وحمِّله عبر USB — أو استخدم زر التحميل المدمج للقيام بذلك عبر البلوتوث/WebUSB.
  4. انتقل إلى تبويب ▶️ تشغيل، اضغط 📡 اضغط للاتصال!، وابدأ بالتحكم في الـ micro:bit.

خطوة بخطوة: الاستنساخ والتحميل والاختبار

يأخذك هذا الدليل من نسخة فارغة إلى جهاز تحكم مُتحقَّق من عمله: أداة واحدة تُرسَل بنجاح في كل اتجاه.

1. استنساخ المستودع

git clone https://github.com/abourdim/bit-rxy.git
cd rxy

2. تشغيل الموقع محليًا

لا توجد خطوة بناء، لكن Web Bluetooth/WebUSB يرفضان مسار file:/// المباشر:

npx serve .

افتح رابط http://localhost:... المعروض في Chrome أو Edge (النسخة المباشرة على GitHub Pages تعمل بنفس الطريقة دون أي إعداد).

3. بناء جهاز تحكم بسيط

في تبويب ✏️ بناء، اسحب أداة زر واحدة وأداة LED واحدة إلى اللوحة. هذا أصغر اختبار ذهاب وإياب ممكن: مدخل واحد، مخرج واحد.

4. الحصول على الكود وتحميله

اضغط 📄 الكود لفتح كود MakeCode المولَّد. إما أن تنسخه إلى makecode.microbit.org وتحمِّله عبر USB بالطريقة المعتادة، أو جرّب زر التحميل المدمج، الذي يحاول تجميع الكود وإرساله مباشرة إلى لوحة متصلة عبر البلوتوث أو WebUSB (راجع فهم الكود لمعرفة آلية العمل ومسار الرجوع عند فشل التجميع).

5. اختبار اتجاه الإدخال (التطبيق ← micro:bit)

انتقل إلى ▶️ تشغيل، اضغط 📡 اضغط للاتصال!، اختر لوحتك، ثم اضغط على أداة الزر. يجب أن يستجيب الـ micro:bit فورًا (المعالج المولَّد افتراضيًا يعرض أيقونة قلب).

6. اختبار اتجاه الإخراج (micro:bit ← التطبيق)

في محرر MakeCode، أضف سطرًا لإرسال قيمة: sendValue("your_led_id", "1") داخل كتلة ضغط زر أو كتلة متكررة، أعد التحميل، وتأكد من إضاءة أداة LED في التطبيق عند تفعيلها.

يبدو الأساس الناجح كالتالي: يعرض الـ micro:bit قلبًا عند الضغط على أداة الزر، وتضيء أداة LED في التطبيق عندما يستدعي الفيرموير sendValue() — تم التحقق من كلا اتجاهي البروتوكول بشكل مستقل.

فهم الكود (للمبتدئين)

لمن لديه التطبيق قيد التشغيل ويريد فتح الكود المصدري والبدء بتعديل شيء ما. يفترض معرفة أساسية بـ JavaScript لكن لا شيء خاص بهذا الكود تحديدًا. تخطَّ هذا القسم إذا كنت تريد فقط استخدام التطبيق.

الفرق الجوهري عن التطبيقات الثلاثة الأخرى في هذه المجموعة: الـ micro:bit ليس مجرد جهاز تحكم طرفي ثابت — بل يحمل إعداداته الخاصة. اربط أي نسخة من هذا التطبيق بلوحة مُحمَّلة وستعيد رسم التخطيط الذي تم دمجه فيها بأمانة عند التحميل.

مولّد الكود: من اللوحة إلى الفيرموير

generateDemoCode(cfg) يأخذ قائمة الأدوات الحالية، ولكل أداة، يُصدر كتلة if (id == "...") مطابقة في قالب الفيرموير — أداة الزر تحصل على كتلة «عند الضغط، اعرض قلبًا»؛ والمنزلق يحصل على كتلة «اقرأ القيمة، ارسم رسمًا بيانيًا شريطيًا»؛ وهكذا لكل الأنواع الـ16 من الأدوات. كل معالج مولَّد بسيط عمدًا ومُعلَّق عليه بـ // Add your code here! — فالهدف منه أن يكون نقطة انطلاق تعدّلها في MakeCode، وليس برنامجًا جاهزًا.

function generateDemoCode(cfg) {
  const b64 = btoa(unescape(encodeURIComponent(JSON.stringify(cfg))));  // Unicode-safe (handles emoji labels!)
  const buttons = cfg.widgets.filter(w => w.t === 'button');
  const sliders = cfg.widgets.filter(w => w.t === 'slider');
  // ...one filter per widget type...

  let buttonCode = buttons.map(w => `    if (id == "${w.id}" && val == "1") {
        basic.showIcon(IconNames.Heart)
        // Add your code here!
    }`).join('\n');
  // ...same pattern for every other widget type, then stitched into
  // the firmware template alongside the embedded CFG Base64 string...
}

كيف يبقى التخطيط محفوظًا على الـ micro:bit نفسه

يتم تحويل تخطيط الأدوات بأكمله إلى JSON، ثم ترميزه بـ Base64 (عبر سلسلة btoa(unescape(encodeURIComponent(...))) متوافقة مع Unicode كي تنجو التسميات التي تحتوي على رموز تعبيرية)، ثم دمجه مباشرة في الفيرموير المولَّد كثابت نصي. يعرف الفيرموير بعدها كيفية إعادة إرسال تلك السلسلة عبر البلوتوث على شكل أجزاء من 18 بايت كلما طُلب منه ذلك:

const CFG = "${b64}"   // baked in at generation time

bluetooth.onUartDataReceived(serial.delimiters(Delimiters.NewLine), function() {
    let cmd = bluetooth.uartReadUntil(serial.delimiters(Delimiters.NewLine))
    if (cmd == "GETCFG") {
        bluetooth.uartWriteLine("CFGBEGIN")
        for (let i = 0; i < CFG.length; i += 18) {
            bluetooth.uartWriteLine("CFG " + CFG.substr(i, 18))
        }
        bluetooth.uartWriteLine("CFGEND")
    } else if (cmd.indexOf("SET ") == 0) {
        let parts = cmd.substr(4).split(" ")
        handleWidget(parts[0], parts.slice(1).join(" "))
    }
})

18 بايت لكل جزء يبقي كل سطر ضمن حد MTU للبلوتوث (حوالي 20 بايت) المستخدم في كل هذه المجموعة من التطبيقات. من جهة المتصفح، يُفكّ ترميز الـ Base64 المُعاد تجميعه ليعود إلى تخطيط الأدوات بالضبط كما بنيته — وهذا ما يتيح لتبويب التشغيل عرض جهاز التحكم بشكل صحيح حتى في جلسة متصفح لم تفتح تبويب البناء إطلاقًا.

التحميل بضغطة واحدة: خدمة التحميل الجزئي وWebUSB

بالإضافة إلى المسار المعتاد «انسخ الكود إلى MakeCode»، تحاول flashToMicrobit() تجميع الكود المولَّد عبر خدمة تجميع MakeCode ودفع ملف .hex الناتج مباشرة إلى اللوحة عبر البلوتوث، باستخدام خدمة التحميل الجزئي في الـ micro:bit — وهي ميزة DAL حقيقية (المعرّف UUID e97dd91d-...) تتيح للوحة سبق تحميلها عبر USB قبول تحديثات البرنامج عبر BLE دون كابل:

const PFS_SERVICE = 'e97dd91d-251d-470a-a062-fa1922dfa9a8';
const PFS_CHAR    = 'e97d3b10-251d-470a-a062-fa1922dfa9a8';
const PFS_CMD = { REGION_INFO: 0x00, FLASH_DATA: 0x01, END_OF_TX: 0x02, STATUS: 0xEE, RESET: 0xFF };

إذا فشلت خطوة التجميع لأي سبب، لا يستسلم التطبيق — بل يفتح MakeCode في تبويب جديد ليتمكن المستخدم من التجميع والتحميل يدويًا. يوفر مسار منفصل flashViaUSB() نفس راحة «التحميل دون مغادرة المتصفح» عبر اتصال USB مباشر (WebUSB) بدلًا من البلوتوث، للوحات التي لم تُقترَن بعد.

إعادة الاتصال بشكل نظيف: تنظيف مستمعي BLE

يوثّق هذا القسم الفرعي خطأ إعادة اتصال حقيقيًا وإصلاحه (الالتزام 26730c4) — مفيد إذا كنت تُعدّل connectBle() بنفسك.

كل استدعاء لـconnectBle() ينفّذ:

notifyChar.addEventListener('characteristicvaluechanged', onNotify);

من المغري افتراض أن تكرار هذا آمن — إضافة نفس المستمع لنفس الحدث على نفس الكائن مرتين لا تفعل شيئًا عادةً في المرة الثانية. المشكلة: تُعيد Web Bluetooth كائن خاصية مُغلّف جديدًا في كل استدعاء لـgetCharacteristic()، حتى لنفس الخاصية الفعلية. لذا فهو ليس أبدًا نفس الكائن، وإضافة المستمع ليست أبدًا تكرارًا غير ضار.

قبل الإصلاح، لم يكن أي شيء يستدعي removeEventListener() المطابقة عند الانقطاع أو إعادة الاتصال. النتيجة: كل نقرة على «اتصال» بعد إعادة تحميل الفيرموير (أو أي انقطاع آخر في الوصلة) كانت تترك مستمع onNotify جديدًا معلّقًا على كائن خاصية جديد، دون إزالة السابقين أبدًا. كان إشعار BLE حقيقي واحد ينتهي به الأمر بإطلاق onNotify() عدة مرات — مرة لكل مستمع قديم لا يزال متصلًا — مما يُضاعف ويُفسد بصمت تدفق CFG المستلم.

هذا ما يفسّر عرضًا محيّرًا لوحظ أثناء تصحيح فيرموير ESP32 المرافق: كان عدد كتل CFG المستلمة يتجاوز أحيانًا المجموع الحقيقي (مثلًا 91 مستلمة مقابل نحو 60 متوقعة) بعد عدة عمليات إعادة اتصال في نفس علامة التبويب، دون إعادة تحميل الصفحة بينها.

الإصلاح، في connectBle() وonDisconnect():

// في بداية connectBle()، قبل أي اتصال جديد:
if (state.ble.notifyChar) {
  state.ble.notifyChar.removeEventListener('characteristicvaluechanged', onNotify);
}
if (state.ble.device?.gatt?.connected) {
  state.ble.device.gatt.disconnect();
}

// في onDisconnect()، قبل إعادة ضبط state.ble:
if (state.ble.notifyChar) {
  state.ble.notifyChar.removeEventListener('characteristicvaluechanged', onNotify);
}

الدرس العام: في واجهة برمجية لا يضمن توثيقها صراحة هوية الكائنات المُعادة، لا تفترض أبدًا أن كائنًا «مكافئًا» تم الحصول عليه مرتين هو نفس الكائن من منظور addEventListener(). نظّف المستمع السابق صراحة قبل إرفاق مستمع جديد.

اللغات

ترجمة كاملة إلى الإنجليزية والفرنسية والعربية تشمل الترويسة، منتقي القوالب، شريط أدوات البناء، لوحة الأدوات، لوحة الخصائص، شاشة التشغيل، الدليل التعليمي، شاشة التحميل، نافذة الكود، والإشعارات لكل إجراء أساسي — باستخدام أداة مساعدة tr(path, vars) تبحث بمفتاح مُركَّب بنقاط داخل كائن I18N (مثال: tr('toast.sizeSet', {w, h})) مع استبدال {placeholder} بالقيم الديناميكية. تقلب العربية الصفحة بأكملها إلى dir="rtl" وتستخدم العلم الجزائري، مثل بقية هذه المجموعة من التطبيقات.

على عكس الاكتشاف التلقائي للغة المتصفح المستخدَم سابقًا، يبدأ التطبيق الآن مباشرة بالفرنسية عند أول زيارة ولا يتغير إلا باختيار صريح، محفوظ في مفتاح kid_lang الخاص به في localStorage — مثل Bit-Bot وTalking Robot وmicro:bit Playground.

تُركت عمدًا بالإنجليزية: تسميات كل حقل في نموذج خصائص الأدوات (Width، Height، Min، Max، إلخ — نحو 100 نص موزّعة على الأنواع الـ16 من الأدوات) ولوحة «Helper Tools» المخصصة للمستخدمين المتقدمين (Group، Layers، Ruler، Align، Distribute، Canvas Background، Screenshot، Share — جميعها مخفية خلف زر مخصص للتطوير، لا تظهر أبدًا للمستخدمين العاديين)، بنفس حدود النطاق التي رُسمت للوحة Commands المستبعدة في Bit-Bot.

تعذّر الاتصال بالـ micro:bitتأكد من تفعيل البلوتوث، وأن اللوحة تعرض ❤️ (جاهزة)، وأن جهازًا واحدًا فقط متصل في كل مرة — أعد التحميل وحاول مجددًا إذا لم تُغلَق جلسة سابقة بشكل نظيف.
التخطيط المستلم يبدو تالفًا أو غير مكتمل بعد عدة عمليات إعادة اتصال في نفس علامة التبويبأُصلح في الالتزام 26730c4 — انظر إعادة الاتصال بشكل نظيف أعلاه. في نسخة محدّثة، تُنظّف كل إعادة اتصال المستمع BLE السابق؛ في نسخة أقدم، أعد تحميل الصفحة بأكملها بدلًا من مجرد النقر على اتصال مرة أخرى.
الاتصال يفشل دائمًا على iPhone/iPadلا يدعم iOS بروتوكول Web Bluetooth إطلاقًا في Safari أو أي متصفح آخر على iOS (جميعها تعتمد على WebKit) — هذه محدودية في المنصة، وليست خللًا. يكتشف التطبيق ذلك ويوجّه إلى متصفح "Bluefy" المجاني (ابحث عنه في App Store) بدلًا من مجرد عرض «فشل الاتصال».
الأدوات لا تفعل شيئًاتأكد من أن الكود المولَّد قد حُمِّل فعلًا، وأن معرّفات الأدوات في الفيرموير تطابق المعرّفات المعروضة في لوحة الكود — أعد التوليد والتحميل بعد أي تغيير في التخطيط.
فشل التحميل عبر البلوتوث بضغطة واحدةتتطلب خدمة التحميل الجزئي لوحة تعمل بالفعل بنسخة MakeCode متوافقة نتيجة تحميل سابق عبر USB؛ إذا فشلت خطوة التجميع تمامًا، يفتح التطبيق MakeCode في تبويب جديد للتحميل يدويًا.
الـ micro:bit ينقطع عشوائيًاابقَ ضمن نطاق البلوتوث (~10 أمتار)، تحقق من البطارية، وقلّل من تكرار استدعاء sendValue() إذا كنت تُغرق الاتصال.
لوحة الاتجاه لا تعرض أي سهمأعد توليد الكود بعد أي تغيير في تبويب البناء وأعد التحميل — الفيرموير القديم لن يعرف عن أداة أُضيفت لاحقًا.
